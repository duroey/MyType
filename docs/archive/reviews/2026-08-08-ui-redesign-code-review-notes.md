# Type4Me 设置窗口 UI 改造：Code Review 说明

> **归档文档 · 历史审查说明（2026-08-08）**：内容对应当时 UI 改造，不代表当前实现规范。当前文档入口见 `docs/README.md`。

## 1. 文档目的

本文档覆盖本轮设置窗口 UI 改造的完整范围，供代码审查、回归测试和后续维护使用。

本轮工作的目标不是更换业务能力，而是统一设置窗口的信息架构与视觉语言，并修复在实际使用中暴露出的响应式布局、列表滚动和交互一致性问题。除 Modes 增加 `description` 字段外，历史记录、热词和片段替换的持久化格式没有变化。

## 2. 改造目标

- 使用完整、统一的窗口底色承载所有内容。
- 将左侧导航做成有四周层级感的悬浮圆角区域。
- 保留原生 macOS 窗口按钮及其全屏、分屏交互。
- 将高频入口留在一级导航，将低频配置集中到“设置”二级页签。
- 新增首页概览，集中展示 Modes、快捷键和使用统计。
- 统一词汇管理、历史记录与批量编辑界面的组件语言。
- 控制长列表的滚动范围并降低滚动期间的 SwiftUI 布局负担。
- 在较窄窗口下保持内容可读，不允许侧栏或模式列表被压坏。

## 3. 最终信息架构

### 一级导航

1. 首页
2. 词汇
3. 历史
4. 设置（固定在侧栏底部）

### 设置二级胶囊页签

3. 模式
4. 关于

原有账户、版本更新提示、会员版 Debug 等条件逻辑继续保留。更新提示从原“关于”一级入口移动到“设置”入口及“关于”二级页签。

## 4. 视觉系统与窗口层级

### 4.1 统一底层背景

设置窗口现在由一个完整的白色底层承载，标题栏、安全区、正文周边不再使用不同颜色拼接。内容区域与窗口上下左右边缘因此属于同一视觉层。

### 4.2 悬浮侧栏

- 侧栏宽度：224 pt。
- 左侧、上侧、下侧留白：10 pt。
- 圆角：26 pt，连续圆角。
- 侧栏没有硬分割线，依靠轻微灰度差建立层级。
- 窗口最小尺寸：900 × 600 pt，防止侧栏留白和正文内容被继续挤压。

### 4.3 原生窗口按钮

窗口关闭、最小化、缩放按钮仍使用 `NSWindow.standardWindowButton`，没有使用自绘按钮：

- 第一枚按钮距窗口左边缘 25 pt。
- 三枚按钮顶部距窗口上边缘 25 pt。
- 后两枚按钮按原生间距排列。
- 侧栏为按钮到产品 Logo 预留 25 pt 的视觉间距。

由于缩放按钮仍是原生按钮，鼠标悬浮时保留 macOS 的全屏与分屏菜单。

### 4.4 设计令牌

`TF` 中增加并统一了设置窗口相关颜色：

- `settingsWindowBackground`：窗口底层。
- `settingsSidebar` / `settingsSidebarActive` / `settingsSidebarHover`：侧栏状态。
- `settingsControl`：`#F1F1F1`，胶囊和控件默认底色。
- `settingsControlHover`：`#E8E8E8`，控件悬浮底色。
- `settingsRowHover`：`#F8F8F8`，列表行悬浮底色。
- `settingsBorder`：低对比度边框。

主要操作按钮统一为黑色；蓝、绿、红只承担必要的状态或危险语义。

## 5. 首页

### 5.1 页面内容

- 新 Slogan：中文“说出想法，即刻成文”，英文“Say it. Shape it.”。
- “我的模式”列表展示所有 Modes，但不在首页展开或编辑详情。
- 右上角“管理”按钮跳转到设置下的 Modes 编辑页。
- 每个 Mode 展示名称、描述、快捷键及快捷键触发方式。
- 快捷键触发方式明确区分“按住录制”和“按下切换”。

### 5.2 使用统计

首页统计区域展示：

- 输入总时间。
- 总字数。
- 输入速度。
- 估算节约时间。

节约时间采用 40 字/分钟的假设打字速度：

```text
estimatedTypingSeconds = totalCharacters / 40 × 60
savedSeconds = max(0, estimatedTypingSeconds - totalRecordingDuration)
```

统计项常态仅显示统一尺寸的 SF Symbols 图标和数字；悬浮时在指标左侧显示即时黑色 Tooltip。

### 5.3 数据刷新

每次用户重新进入首页时都会重新：

- 从 `ModeStorage` 加载 Mode 列表及排序、名称、描述和快捷键。
- 从 `HistoryStore` 加载最新统计。

因此用户从 Modes 编辑页返回首页后，不再看到旧排序或旧名称。

### 5.4 响应式行为

- 宽度充足时展示 Mode 列表和右侧统计栏。
- 宽度不足时通过 `ViewThatFits` 隐藏统计栏，优先保证 Mode 列表可读。
- Mode 卡片最小宽度为 520 pt。
- 窗口本身有 900 pt 最小宽度，侧栏的 10 pt 悬浮边距不会被压缩消失。

### 5.5 背景装饰

首页使用 `Canvas` 绘制高密度、45° 透视的浅灰点阵波形。它不参与命中测试，也不包含额外卡片，避免右下角出现无意义的视觉块。

## 6. Modes 数据格式与兼容策略

### 6.1 新字段

`ProcessingMode` 新增：

```swift
var description: String
```

该字段只用于首页和 Modes 管理界面的说明文字，不会作为 Prompt 发送给模型。

新写入的 `modes.json` 会持久化该字段。Modes 编辑页增加“描述”输入框，并纳入未保存状态判断和保存逻辑。

### 6.2 旧数据兼容

解码使用 `decodeIfPresent`：

- 旧数据缺少 `description` 时不会解码失败。
- 官方 Mode 根据稳定 UUID 补充内置默认描述。
- 旧的自定义 Mode 保持空描述，不从 Prompt 猜测含义。
- 首页遇到空描述时显示通用的“自定义处理模式”。

`ModeStorage` 在内置 Mode 合并、旧 ID 迁移和 Legacy Mode 迁移时都会保留用户已经填写的描述。

### 6.3 自动化测试

`ModeStorageTests` 新增覆盖：

- 自定义描述保存与重新加载。
- JSON 中确实写入 `description`。
- 旧官方 Mode 自动获得默认描述。
- 旧自定义 Mode 缺少字段时保持空字符串。

## 7. 词汇管理

### 7.1 页面结构

原 ASR 热词 / 片段替换上下结构改为胶囊 Tab：

- 默认背景 `#F1F1F1`。
- Hover `#E8E8E8`。
- Active `#FFFFFF`。
- 页签名称不在内容区重复出现。
- 当前页签说明直接放在页签下方。

页面外层固定，只有“新增词条”以下的列表区域滚动，长词库不会带动整个页面滚动。

### 7.2 共用工具栏

ASR 热词和片段替换共用：

- 可展开搜索控件。
- 排序按钮。
- 批量编辑按钮。

搜索的收起态和展开态是同一个控件，通过宽度和内容过渡完成动画。搜索同时过滤热词、片段替换内容和触发词。

工具栏使用图标按钮；Tooltip 使用无延迟的黑色圆角样式并显示在控件下方。

### 7.3 ASR 热词

- 新增热词入口移到列表第一行并独占一行。
- 热词显示为可编辑胶囊，而不是小型只读文本。
- 默认不显示编辑和删除按钮。
- Hover 时高亮胶囊并显示编辑、删除操作。
- 编辑支持保存、取消和回车提交。
- 排序支持按添加时间和首字母切换。

### 7.4 片段替换

- 新增区和列表统一为同一视觉语言。
- 新增时左侧为“替换内容”，右侧为“触发词”，与列表阅读顺序一致。
- 触发词输入框提示用户按回车继续添加；回车后生成可移除的触发词胶囊。
- 同一替换内容支持多个触发词。
- 列表改为单行高密度布局：替换内容在左，触发词组在右。
- Hover 时显示编辑、删除操作，避免常态噪音。
- “全局生效”与应用作用域继续保留，添加应用按钮缩小到与作用域胶囊协调的尺寸。
- 添加应用、添加条目等图标按钮均有即时 Tooltip，并通过层级处理避免被下方列表遮挡。

### 7.5 批量编辑弹窗

热词和片段替换的批量编辑弹窗改用当前主窗口的卡片、灰度和按钮语言；保存按钮改为黑色主按钮。底层解析与存储逻辑保持不变。

## 8. 历史记录

### 8.1 信息层级

历史页重新组织为：

- 标题与说明。
- 总时长、总字数、平均速度统计卡。
- 搜索、日期筛选、批量选择、导出工具栏。
- 按日期分组的记录列表。
- 行展开详情、纠错、复制和删除操作。

列表常态保留操作按钮需要的尾部宽度。Hover 只改变按钮透明度和背景，不再导致正文重新排版。

### 8.2 独立滚动区域

历史页使用固定外层，记录列表内部滚动。搜索栏和统计信息不会随大量记录一起滚出页面。

### 8.3 滚动性能修复

早期实现中，`LazyVStack` 的直接子节点是“日期分组”，但每个分组内部仍使用普通 `VStack` 一次创建全部记录。单日记录较多时，大量离屏行仍会创建 `.onHover` 响应器，滚动过程中会使 SwiftUI AttributeGraph 进入持续布局和命中测试循环，表现为：

- 页面在尚未到底时卡死。
- CPU 持续接近 100%。
- 停止滚动后 CPU 不回落。

最终实现将每条记录直接作为 `LazyVStack` 的懒加载子节点。离屏行不再提前创建 Hover 响应器。

同等强度连续滚动压力测试中，CPU 在滚动期间约为 50%，停止后依次回落到约 10%、0%，没有再次出现持续 100% 或界面无响应。

### 8.4 Tooltip 溢出策略

普通工具栏使用共享的 SwiftUI 即时 Tooltip。记录行尾部按钮需要允许 Tooltip 超出列表首尾边界，因此使用一个非激活、忽略鼠标事件的 `NSPanel`：

- 不属于 `ScrollView` 子视图，不会被裁切。
- 根据当前鼠标所在屏幕约束位置，防止越过可见屏幕边缘。
- 行离屏或 Hover 结束时立即销毁。
- 不在滚动期间持续读取 Geometry，避免重新引入性能问题。

### 8.5 纠错界面

- 文本选区反馈改为黑色强调，而不是蓝色。
- “添加”主按钮改为黑色，而不是绿色。
- 选中项使用黑底白字，保持当前设置窗口语言。

## 9. 共享组件整理

为了降低页面间的重复实现，本轮收口增加：

- `SettingsTooltipBubble`：统一黑色 Tooltip 外观。
- `settingsTooltip`：统一即时 Hover 响应和动画。
- 设置控件灰度令牌：统一默认、Hover、行 Hover 状态。
- 各设置子页的 `showsHeader` 参数：子页独立使用时可显示原标题，嵌入设置胶囊容器时避免重复标题。

记录行 Tooltip 的 AppKit Panel 仍单独保留，因为它解决的是 `ScrollView` 裁切问题，与普通 Tooltip 的布局约束不同。

## 10. Debug 辅助入口

Debug 构建支持启动参数：

```bash
.build/debug/Type4Me --open-settings
```

该参数仅在 `#if DEBUG` 下生效，用于 UI 迭代时直接打开设置窗口，不改变 Release 启动流程。自动打开窗口最多重试 20 次，避免窗口创建异常时无限轮询。

## 12. 建议 Reviewer 重点检查

### 高优先级

1. `SettingsWindowConfigurator` 对不同 macOS 版本、全屏进出和窗口重建时的原生按钮约束是否稳定。
2. `ProcessingMode.description` 在真实旧版 `modes.json`、官方 Mode 合并和自定义 Mode 上的兼容结果。
3. 历史记录逐行懒加载后，分组圆角、展开状态、批量选择和加载更多是否正确。
4. `HistoryFloatingTooltipController` 在多显示器、屏幕边缘和快速移出窗口时是否及时释放 Panel。
5. 词汇列表在大数据量、搜索、切换应用作用域和批量保存后的刷新一致性。

### 中优先级

1. 中英文文案长度下的胶囊页签、统计值和输入框缩放。
2. 900 × 600 最小窗口下首页、词汇、历史和设置四类页面的可读性。
3. 会员版条件编译下“模型”“账户”“Debug”和更新角标的入口。
4. 键盘操作、VoiceOver 标签和仅图标按钮的可访问性。
