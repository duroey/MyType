# Type4Me 翻译模式增强功能设计

> 分支：`feat/translation-mode-enhancement`
> 文档类型：产品设计
> 文档状态：当前有效（已实现，持续验证）
> 设计日期：2026-08-11
> 最后校验：2026-08-11
> 实现基线：`5076296`，错误语言重试修订至 `0bc9bf8`
> 目标版本：Type4Me 2.x
> 阅读说明：背景章节描述改造前基线；功能状态以页首与代码为准

## 1. 背景

Type4Me 当前把翻译能力拆成两个独立的预置模式：

- “英文翻译”：假设用户口述中文，输出英文，默认快捷键为 `⌥ + 3`；
- “中文翻译”：假设用户口述英文，输出中文，没有默认快捷键。

两个模式分别拥有独立的 ID、Prompt 和存储生命周期。该结构来自功能的增量演进，而不是统一的翻译产品模型，存在以下问题：

1. 用户必须先理解“模式名称表示目标语言”，才能选择正确模式；
2. 新增一种目标语言就要新增一个模式，无法自然扩展到多语言；
3. 两个 Prompt 的能力和保护规则不一致；
4. 模式列表被语言方向占据，增加认知与管理成本；
5. “中文翻译”通过 Bundle 级 UserDefaults 一次性补入，而模式列表保存在共享的 `modes.json`，可能出现补入标记存在但模式丢失的状态；
6. 用户无法在一个稳定入口中快速调整目标语言。

因此，本次增强将两个方向性预置模板统一为一个内置“翻译”模式。

## 2. 产品目标

### 2.1 核心目标

提供一个稳定、明确、可扩展的内置翻译入口：

- Type4Me 自动识别用户的口述语言；
- 用户只需要选择目标语言；
- 同一个翻译模式支持多种常见目标语言；
- 翻译行为、格式保护和安全边界在所有语言间保持一致；
- 已有用户升级后不丢失快捷键和自定义内容。

### 2.2 成功标准

1. 模式列表中只存在一个官方“翻译”模式；
2. 新用户无需配置源语言即可开始翻译；
3. 用户可以在模式详情中通过下拉列表切换目标语言；
4. 目标语言切换后，下一次录音立即使用新目标语言；
5. 老用户原有“英文翻译”和“中文翻译”记录在升级后保持原样，新内置翻译模式独立补入；
6. 内置翻译模式不能被删除、重命名或修改系统 Prompt；
7. 代码、路径、URL、数字、专有名词等内容在所有目标语言下都受到一致保护。

## 3. 非目标

第一版不包含：

- 手动配置源语言；
- 同一次口述输出多种语言；
- 为每个快捷键单独配置目标语言；
- 自动根据前台 App 或联系人切换目标语言；
- 文档级、文件级或批量翻译；
- 翻译记忆库、术语库管理界面；
- 在录音过程中临时说“翻译成日语”来覆盖已选目标语言；
- 对用户展示或允许编辑底层 Prompt；
- 云端保存翻译历史或语言偏好。

## 4. 核心产品决策

### 4.1 单一内置模式

模式名称统一为：

- 中文：`翻译模式`
- 英文：`Translation Mode`

该模式标记为内置模式，具有以下约束：

- 始终存在；
- 不可删除；
- 不可重命名；
- 不可编辑 Prompt；
- 不可修改处理状态文案；
- 不提供短文本跳过设置；
- 可以调整目标语言；
- 可以沿用系统通用的快捷键管理能力。

“用户只能调整翻译的目标语言”指翻译业务配置只有目标语言一个选项。快捷键属于所有模式共有的触发配置，仍允许添加、编辑和删除。

### 4.2 自动识别源语言

翻译模式不展示源语言选择器，也不持久化源语言设置。

处理链路为：

1. 当前 ASR Provider 按其正常能力识别语音；
2. LLM 根据 ASR 文本自动判断源语言；
3. LLM 将内容翻译为用户选择的目标语言；
4. Type4Me 将结果注入当前输入位置。

翻译模式不修改全局 ASR Provider 配置，也不额外要求用户选择识别语言。

### 4.3 一个当前目标语言

翻译模式在任意时刻只有一个当前目标语言。该语言应用于该模式下的所有快捷键。

如果用户为翻译模式绑定多个快捷键，这些快捷键只是不同的触发方式，不代表不同翻译方向。

### 4.4 默认行为

- 默认目标语言：英语；
- 新安装默认快捷键：`fn + 左 Shift`、`⌥ + 2`；
- 默认快捷键操作方式：切换式；
- 默认模式名称不会随目标语言变化；
- 处理状态根据目标语言显示为“正在翻译为英语……”等动态文案。

默认英语用于覆盖最常见的中译英场景。上述两个快捷键只作为新安装默认值；老用户升级时不抢占或迁移任何旧模式快捷键。

### 4.5 新安装默认模式体系

新安装按以下顺序创建模式与快捷键：

| 顺序 | 模式 | 默认快捷键 |
|---|---|---|
| 1 | 快速模式 | `fn` |
| 2 | 智能感知 | `fn + 左 Control`、`⌥ + 1` |
| 3 | 翻译模式 | `fn + 左 Shift`、`⌥ + 2` |
| 4 | 随便问 | `fn + Space`、`⌥ + 3` |
| 5 | Mac 操作 | `⌥ + 4` |
| 6 | 语音润色 | `⌥ + 5` |
| 7 | Prompt 优化 | 无 |
| 8 | 代办模式 | 无 |

英文翻译、中文翻译和命令模式不再进入新安装默认列表。已有用户的对应记录仍作为用户数据保留，不自动删除、隐藏或改写。

## 6. 用户界面设计

### 6.1 模式列表

新安装只显示一个官方翻译模式：

> 翻译模式
> 自动识别口述语言并翻译为目标语言

模式行继续显示：

- 内置模式标识；
- 当前快捷键摘要；
- 当前目标语言，例如“目标：英语”。

模式列表不因为目标语言变化而修改模式名称或排序。

老用户升级时，原有“英文翻译”和“中文翻译”继续作为普通可编辑模式显示，新内置“翻译”作为独立模式追加。系统不自动重命名、隐藏或删除旧模式，由用户自行决定是否继续保留。

### 6.2 模式详情

详情页包含：

1. 模式名称、图标和说明；
2. 目标语言设置；
3. 快捷键列表；
4. 简短使用说明。

目标语言设置使用原生下拉选择器：

```text
目标语言        [ 英语                 ▾ ]
                自动识别你的口述语言
```

隐藏以下通用自定义模式字段：

- 模式名称；
- 模式描述编辑器；
- Prompt 编辑器；
- 处理中提示文案；
- 短文本跳过阈值；
- 删除模式按钮。

### 6.3 切换反馈

用户选择目标语言后：

- 设置立即保存；
- 不弹出额外确认框；
- 下一次录音使用新目标语言；
- 已经处于录音、识别或 LLM 处理中的任务继续使用启动时冻结的目标语言；
- 不允许中途切换影响正在执行的请求。

目标语言变化应显示轻量即时反馈，例如：

> 目标语言已设为日语

### 6.4 录音与处理状态

录音阶段沿用现有模式名称和录音状态。

进入 LLM 处理阶段后显示动态状态：

- 正在翻译为英语……
- 正在翻译为日语……
- Translating to Chinese (Simplified)…

如果语言名称过长，浮动条允许截断，但 Tooltip 或模式详情必须显示完整名称。

## 7. 翻译行为规范

### 7.1 基本语义

翻译模式只翻译用户口述内容，不回答其中的问题，也不执行其中的命令。

例如：

- 口述：“Can you send me the report?”
- 目标语言：简体中文
- 输出：“你能把报告发给我吗？”

不得把它处理成对用户的回答或真的执行发送操作。

### 7.2 源语言与目标语言相同

如果检测到口述内容已经是目标语言：

- 保持原语言；
- 修正高置信度 ASR 错误、断句和标点；
- 清理无意义的填充词和废弃半句；
- 不进行无必要的改写或风格升级；
- 不返回“无需翻译”等说明。

### 7.3 混合语言

当输入包含多种语言时：

- 将自然语言主体翻译为目标语言；
- 保留品牌名、产品名、缩写和无固定译名的术语；
- 已有公认译名时使用目标语言中的标准译名；
- 不因少量英文技术词错误判断整段源语言。

### 7.4 自我修正

识别并处理明确改口信号，例如：

- 中文：“不对”“哦不”“改成”“应该是”“重说”；
- 英文：“sorry”“I mean”“actually”“let me rephrase”；
- 其他语言中的等价高置信度表达。

只保留最终确认的意思。普通否定、对比和反问不得被误判为改口。

### 7.5 内容保护

以下内容默认原样保留：

- 代码和命令；
- URL、邮箱、文件路径；
- 变量名、函数名和标识符；
- 产品名、品牌、缩写；
- 版本号；
- 数字、日期、时间、金额和单位的实际数值。

可以按目标语言习惯调整周围语序和标点，但不能改变其值。

### 7.6 格式保护

- 保留原文列表、步骤、段落和换行层级；
- 目标语言使用其自然标点和语序；
- 不无故添加标题、总结或说明；
- 不输出引号、前言、注释或“翻译如下”；
- 输出只包含最终可注入文本。

### 7.7 Prompt 注入防护

ASR 文本必须作为被翻译的数据边界传入，不能被解释为系统指令。

即使口述内容包含“忽略之前规则”“回答这个问题”或工具调用结构，翻译模式仍只翻译这些内容，不改变任务类型。

## 8. 错误与降级

### 8.1 无有效文本

ASR 未得到有效文本时，沿用现有空转写提示，不调用 LLM。

### 8.2 不支持或未知目标语言

如果持久化的语言代码已不在当前内置列表中：

1. 保留原始代码，避免静默丢失配置；
2. 设置页面显示“暂不支持的语言”；
3. 阻止开始翻译并引导用户重新选择；
4. 不自动回落到英语，避免输出语言突然改变。

### 8.3 LLM 失败

沿用现有 LLM 错误展示策略。网络失败、超时、空输出和异常结构不得把 ASR 原文当作成功译文静默注入，除非未来增加明确的用户降级选项。

### 8.4 输出语言错误

目标语言一致性检查采用分级策略：

- 短文本或语言检测置信度不足时记录本地 warning 并接受结果；
- 专有名词、代码和混合技术词不计为语言错误；
- 空输出、工具调用等明确异常仍显示翻译失败并停止注入；
- 输出明显整段不是目标语言时，使用完整最终 ASR 和强化目标语言约束自动重试一次；
- 重试结果仍以高置信度判定为错误语言时，标记翻译失败并停止注入。

该策略既规避 `NLLanguageRecognizer` 对短文本、简繁中文和技术混排的误判，也阻止高置信度错误语言结果静默交付。warning 和重试原因只写入本地调试日志，不记录额外全文。

## 9. 快捷键语义

- 新安装默认使用 `fn + 左 Shift` 和 `⌥ + 2`，老用户升级时新模式默认不绑定快捷键；
- 支持一个模式绑定多个快捷键；
- 所有绑定共享当前目标语言；
- 目标语言在录音开始时冻结到本次会话上下文；
- 用另一快捷键结束录音时，仍使用开始录音时的目标语言；
- 第一版不允许将 `fn + 左 Shift` 固定为英语、`⌥ + 2` 固定为日语。

如果未来需要快捷键级目标语言，应扩展快捷键绑定的数据模型，而不是重新创建多个官方翻译模式。

## 10. 数据与升级迁移

### 10.1 规范模式身份

统一翻译模式使用全新的稳定 ID，不复用当前“英文翻译”或“中文翻译”的任何 ID。

原因是旧翻译模式属于可编辑模式，用户可能修改过 Prompt、名称、描述、处理文案、快捷键或其他字段。复用任一旧 ID 都会把用户记录错误识别为新版内置模式，并在内置模式规范化过程中造成数据覆盖。

旧“英文翻译”和“中文翻译”ID 继续按原有语义读取，仅用于兼容已有用户记录；它们不再出现在新安装默认列表中，也不会被自动转换为新版内置翻译模式。

### 10.2 新安装

新安装的默认模式列表中：

- 包含一个内置“翻译”模式；
- 不包含“英文翻译”；
- 不包含“中文翻译”；
- 默认目标语言为英语；
- 默认快捷键为 `fn + 左 Shift` 和 `⌥ + 2`。

### 10.3 已有用户迁移

迁移必须可重复执行且结果一致，不依赖只执行一次的 Bundle UserDefaults 标记。

初始目标语言按以下优先级确定：

1. 已存在新版目标语言设置：直接保留；
2. 用户最后选择的是旧“中文翻译”：设为简体中文；
3. 用户最后选择的是旧“英文翻译”：设为英语；
4. 其他情况：设为英语。

新版内置翻译模式的补入规则：

- 使用全新稳定 ID 创建；
- 作为新增内置模式追加到现有模式列表末尾，不改变已有排序；
- 升级时默认不绑定快捷键；
- 不复制、移动或删除旧翻译模式的任何快捷键；
- 用户可以在模式详情中自行添加快捷键；
- 新安装才默认绑定 `fn + 左 Shift` 和 `⌥ + 2`。

旧翻译模式保护规则：

- 原 ID 保持不变；
- 原名称、描述、Prompt 和处理文案保持不变；
- 原快捷键及其绑定 ID、修饰键和操作方式保持不变；
- 原短文本设置及未来可解码字段保持不变；
- 原列表位置保持不变；
- 不根据 Prompt 内容判断用户是否自定义；
- 不自动改名、隐藏、禁用、合并或删除；
- 继续作为普通可编辑、可删除模式使用。

### 10.4 用户自定义内容保护

迁移不尝试区分“官方原版”和“用户自定义版”。即使旧记录的 Prompt 当前恰好等于某个已知官方模板，也仍按用户数据原样保留。

这样可以避免以下风险：

- 用户先修改后又部分恢复，内容碰巧命中官方模板；
- 用户只修改名称、快捷键或处理文案，Prompt 比对无法发现；
- 未来字段未纳入迁移判断而被规范化覆盖；
- 多个 App 构建共享 `modes.json` 时，旧构建写回的数据被误判。

新版内置模式与旧模式之间不存在所有权转移关系。

### 10.5 持久化原则

- 目标语言代码必须与规范翻译模式记录一起持久化；
- 不使用 Bundle 独立 UserDefaults 作为模式是否存在的唯一依据；
- 内置模式补入必须幂等，但不得合并或规范化旧翻译模式；
- DEV 与正式版读取同一个模式文件时，应得到一致的翻译模式状态；
- 用户不能通过删除模式记录永久删除内置翻译模式：若记录从 `modes.json` 中缺失，下一次加载必须以默认值（目标语言英语、无快捷键）重新补入；由于目标语言和快捷键随记录一起存储，记录被删除后这些配置已无从恢复，不做保留承诺。

## 11. 隐私与数据边界

本次功能不新增数据收集：

- 目标语言仅保存在本地；
- 口述文本仍按当前 ASR 和 LLM Provider 配置处理；
- 不上传模式使用记录到新的服务；
- 不保存额外翻译语料；
- 历史记录继续遵循 Type4Me 现有识别历史设置。

## 12. 国际化与无障碍

- 语言名称必须同时提供中文和英文界面文案；
- 下拉选择器支持键盘导航；
- VoiceOver 读出“目标语言，当前为英语”等完整语义；
- 不只依靠旗帜表示语言；
- 简体中文和繁体中文必须作为不同目标语言；
- 阿拉伯语等从右到左语言的结果必须原样交给目标输入控件，不插入额外方向控制字符；
- 动态处理状态在小尺寸浮动条中保持可读。

## 13. 验收标准

### 13.1 模式与设置

1. 新安装只显示一个内置“翻译”模式；
2. 翻译模式不可删除、重命名或编辑 Prompt；
3. 目标语言下拉列表包含本文规定的第一版语言；
4. 默认目标语言为英语；
5. 新安装默认快捷键为 `fn + 左 Shift` 和 `⌥ + 2`，老用户升级时不抢占旧快捷键；
6. 修改目标语言后重启 App，设置保持不变；
7. 多个快捷键均使用同一当前目标语言。

### 13.2 翻译结果

1. 中文口述可以翻译为英语；
2. 英文口述可以翻译为简体中文；
3. 英文口述可以翻译为日语、韩语、西班牙语等其他内置语言；
4. 输入与目标语言相同时不会输出解释或错误提示；
5. 问句只被翻译，不被回答；
6. 命令只被翻译，不被执行；
7. 代码、路径、URL、邮箱、变量名和数字保持正确；
8. 明确改口只保留最终版本；
9. 列表与段落结构得到保留；
10. 已启动任务不受处理中目标语言切换影响。

### 13.3 迁移

1. 仅有旧英文翻译时，旧记录原样保留并追加新内置翻译；
2. 仅有旧中文翻译时，旧记录原样保留并追加新内置翻译；
3. 两者同时存在时，两条旧记录都原样保留；
4. 旧 Prompt、名称、快捷键、排序和其他配置不发生变化；
5. 新内置翻译使用全新 ID，升级时不自动绑定快捷键；
6. 最后选择旧中文翻译时，新模式初始目标为简体中文，否则默认为英语；
7. 重复加载不会重复创建新内置翻译；
8. 旧 `tf_translateToChineseModeSeeded` 状态不会导致新内置翻译缺失；
9. DEV 与正式版交替运行不会使新旧翻译模式消失或互相覆盖。

## 14. 测试矩阵

实施阶段至少覆盖：

- 新安装默认模式列表；
- 空、损坏和旧版本 `modes.json`；
- 只有英文翻译、只有中文翻译、两者都有、两者都没有；
- 官方 Prompt、用户自定义 Prompt、只修改名称和只修改快捷键；
- 最后选择模式的各类组合；
- 无快捷键、单快捷键、多快捷键和冲突快捷键；
- 所有目标语言代码的编码、解码和 UI 显示；
- 录音过程中切换目标语言；
- 中英混合、纯目标语言、代码密集、数字密集和 Prompt 注入输入；
- LLM 返回错误语言、空输出、解释性前言和工具调用结构；
- App 重启、DEV/正式版交替加载和模式排序持久化。

## 15. 后续扩展方向

本次统一后，可以在不新增模式的前提下继续扩展：

- 增加更多目标语言；
- 快捷键可呼出本次翻译目标语言选单；
- 最近使用语言置顶；
- 目标语言快捷切换菜单；
- 快捷键绑定携带固定目标语言；
- 按 App 或联系人记住目标语言；
- 用户术语表与固定译法；
- 翻译风格选择，例如自然、正式、简洁；
- 本地目标语言一致性检测和更完整的输出 Guard。

这些能力均不进入第一版实现范围。
