## 1. 执行摘要

Type4Me 已经支持通过全局快捷键针对选中文字发起 Ask Anything，并在浮动面板中查看流式回答和继续语音追问。当前会话只存在于内存中：用户关闭面板后无法检索、恢复或继续过去的会话。

本项目为 Ask Anything 增加本地历史会话能力，并明确两个界面的职责：

- **快捷面板**继续承担“现在问”的任务，保持快速、轻量和不中断当前工作的体验；
- **Type4Me 主界面**新增独立的 Ask Anything 页面，承担历史检索、会话管理和长期追问；
- 两个入口共享同一套会话、录音和流式回答状态，不建立两套数据源或两种对话语义。

一句话定义：

> 快捷面板解决“我现在想问什么”，主界面解决“我以前问过什么，以及如何继续”。

---

## 2. 背景与用户问题

### 2.1 当前能力

Ask Anything 当前可以：

- 读取用户明确选中的文本作为问题上下文；
- 通过全局快捷键录制问题；
- 在独立浮动面板中流式显示回答；
- 在同一个面板中连续语音追问；
- 使用快捷键、按钮和 ESC 控制追问录音。

### 2.2 当前缺口

当前会话由 `SelectionAskState.turns` 暂存在内存中，没有持久化会话实体，因此存在以下问题：

1. 关闭面板后无法找回回答；
2. 无法搜索过去问过的问题；
3. 无法在未来继续某个旧会话；
4. 选中文本、问题和回答没有统一的生命周期；
5. 一旦直接把历史管理塞入浮动面板，现有即时体验会被复杂导航和管理操作破坏。

### 2.3 产品机会

Ask Anything 可以从一次性的“选中文字后问一下”，成长为 Type4Me 内的本地对话知识库。但它仍应保持 Type4Me 的语音优先和低打扰特征，不演变为通用聊天客户端。

---

## 3. 产品目标与非目标

### 3.1 产品目标

1. 在不增加首次提问步骤的前提下自动保存有效会话；
2. 让用户在 Type4Me 主界面中检索、阅读和管理历史会话；
3. 允许用户恢复旧会话并继续语音追问；
4. 保持快捷面板当前的尺寸、信息密度和核心操作路径；
5. 保持快捷键、ESC、关闭按钮和录制指示器的既有语义；
6. 确保快捷面板和主界面看到的是同一个实时会话；
7. 将选中文本、问题和回答仅保存在本机，并提供明确的关闭记录与清空入口；
8. 为未来增加最近会话、收藏、标签或同步能力预留稳定的数据模型。

### 3.2 明确非目标

第一版不负责：

- 在快捷面板中提供完整历史列表和管理能力；
- 支持文字输入提问；
- 收藏、标签、文件夹和批量管理；
- 回收站或删除恢复；
- 云端同步或多设备同步；
- 使用 LLM 自动生成标题；
- 语义搜索；
- 导出 Markdown、PDF 或分享链接；
- 多个会话同时录音或生成回答；
- 将 Ask Anything 会话混入现有语音识别“历史”页面；
- 自动总结长会话。

## 4. 核心产品原则

### 4.1 即时体验与长期管理分离

快捷面板只承载当前会话；搜索、重命名、删除等低频管理操作集中到主界面。

### 4.2 一个会话，两种视图

快捷面板和主界面是同一个会话系统的两种展示方式。任何时刻只有一个活动录音或回答任务。

### 4.3 新上下文默认创建新会话

用户在其他 App 中重新选中文字并按快捷键时，系统不得把新问题静默追加到旧会话。

### 4.4 有效内容才进入历史

仅仅唤起面板或开始录音不产生空历史。第一轮问题正式发送时才创建可持久化会话。

### 4.5 本地优先与明确删除

会话默认仅存储在本机。关闭新增历史不会自动删除旧数据；删除或清空必须明确说明影响范围。

### 4.6 保持语音优先

主界面虽然具备完整会话浏览能力，第一版的追问入口仍然是语音，不增加文字聊天框。

## 5. 信息架构

Type4Me 主侧边栏增加一级页面：

1. 首页；
2. 随便问 / Ask Anything；
3. 词汇；
4. 历史；
5. 设置。

“Ask Anything”和现有“历史”保持独立：

| 页面 | 核心对象 | 用户心智 |
|---|---|---|
| Ask Anything | 多轮会话、原始上下文、问题与回答 | 我问过什么，还能继续问什么 |
| 历史 | 语音识别、处理结果和输入日志 | Type4Me 帮我输入过什么 |

## 6. 会话生命周期

### 6.1 创建新会话

以下操作进入新会话草稿：

- 在 Type4Me 外部按下 Ask Anything 快捷键；
- 在主界面 Ask Anything 页面点击“新建会话”；
- 在旧会话菜单中选择“新建会话”。

草稿阶段不出现在历史列表。第一轮问题识别完成并正式提交后，会话及第一轮记录同时创建。

如果没有识别到问题，面板可以显示“没有识别到问题，请重试”，但不创建空会话。

### 6.2 当前会话

快捷面板保持可见时：

- 再次按 Ask Anything 快捷键，开始或结束当前会话的追问；
- 点击“继续追问”，开始当前会话的追问；
- 追问录音中按 ESC，取消并丢弃本轮录音；
- 非录音状态按 ESC，关闭快捷面板；
- 关闭面板不会删除已经形成的会话。

### 6.3 关闭与后台回答

- 回答完成后关闭：立即隐藏面板，会话已经保存；
- 回答生成中关闭：隐藏面板，回答继续在后台生成并写入会话；
- 追问录音中关闭：先取消本轮录音，再关闭面板；
- 请求失败后关闭：保留问题和失败状态，供主界面查看。

### 6.4 下次快捷键触发

快捷面板关闭后，用户在其他 App 中再次按下 Ask Anything 快捷键时，默认创建新会话。系统不自动恢复最近会话。

原因是用户可能已经选中了新的文本；自动恢复会导致新内容与旧上下文意外混合。

### 6.5 恢复历史会话

用户从主界面打开旧会话后，可以继续追问。后续请求使用：

- 该会话最初保存的选中文本；
- 该会话之前成功形成的问题和回答；
- 本次新识别的问题。

用户随后在其他 App 中产生的新选中文本不会替换旧会话上下文。若需基于新内容提问，应创建新会话。

### 6.6 长会话上下文

主界面始终展示完整本地会话。若完整对话超过模型请求的安全上下文预算，系统保留原始选中文本和最近轮次，按时间从最早轮次开始省略请求上下文。

第一版不自动总结被省略的内容。发生省略时，在会话底部显示非阻塞说明：

> 会话较长，后续回答将优先参考最近内容。

## 7. 快捷键行为矩阵

| 当前状态 | 按 Ask Anything 快捷键 | ESC |
|---|---|---|
| 快捷面板未显示，用户位于其他 App | 创建新会话并开始录音 | 沿用标准录音语义 |
| 快捷面板显示，未录音 | 开始当前会话追问 | 关闭面板 |
| 快捷面板正在追问录音 | 结束当前追问录音 | 取消并丢弃本轮追问 |
| 主界面正在查看某个会话且窗口激活 | 继续当前选中会话 | 沿用主窗口系统行为 |
| 主界面处于 Ask Anything 空状态 | 开始新会话录音 | 沿用主窗口系统行为 |
| 主界面位于其他页面 | 显示快捷面板并创建新会话 | 沿用主窗口系统行为 |

现有标准录音中的 ESC 仍表示“取消输入但保留识别、剪贴板和历史”，不得被 Ask Anything 的取消追问语义影响。

## 8. 快捷面板设计

### 8.1 设计范围

现有面板尺寸、问答卡片、选中文本卡片和底部追问栏原则上保持不变。

标题栏新增轻量操作“在 Type4Me 中打开”，使用 Type4Me 横向字标形成品牌化按钮；浅色外观使用黑色字标，深色外观使用白色字标，红点保持不变。

### 8.2 “在 Type4Me 中打开”

点击后依次完成：

1. 打开并激活 Type4Me 主窗口；
2. 切换到 Ask Anything 页面；
3. 选中当前会话；
4. 保持当前流式回答或处理状态；
5. 隐藏快捷面板。

这是展示位置的转移，不是复制或重新发起请求。

该图标按钮的 Tooltip 必须绘制在浮动面板根层或独立浮层中，不得被标题栏、滚动区或卡片容器裁切。

### 8.3 会话状态提示

可以在标题副文案中轻量显示：

- 首轮进行中：“新会话”；
- 已形成多轮：“3 轮对话”；
- 历史关闭时：“本次会话不会保存”。

不在快捷面板新增历史侧边栏、搜索、重命名、删除或批量操作。

## 9. 主界面 Ask Anything 页面

### 9.1 页面结构

页面采用内部双栏结构：左侧会话列表，右侧会话详情。外部仍保留 Type4Me 现有主侧边栏。

```text
┌────────────────────────────────────────────────────────────┐
│ Ask Anything                                               │
├──────────────────────┬─────────────────────────────────────┤
│ 搜索                 │ 会话标题                      ···   │
│ ＋ 新建会话          │ 原始选中内容                        │
│                      │                                     │
│ 今天                 │ 问题 1                              │
│  会话 A              │ 回答 1                              │
│  会话 B              │                                     │
│ 昨天                 │ 问题 2                              │
│  会话 C              │ 回答 2                              │
│                      │                                     │
│                      │          🎙 继续追问                 │
└──────────────────────┴─────────────────────────────────────┘
```

### 9.2 会话列表

顶部包含：

- 搜索框；
- “新建会话”按钮。

会话按照最后活动时间分组：

- 今天；
- 昨天；
- 最近 7 天；
- 最近 30 天；
- 更早。

每个日期分组标题都可折叠或展开，并显示组内会话数量，便于用户收起近期大分组后快速跳转到其他日期范围。折叠时标题文字不得发生颜色闪烁或横向位移；箭头占位保持固定，仅做旋转反馈。

每条会话显示：

- 标题；
- 最后一轮回答摘要；
- 最后更新时间；
- 轮次数量。

大量历史必须使用真正的懒加载列表，避免日期分组一次性创建全部行。

### 9.3 会话标题

默认标题取第一轮问题：

- 清理首尾空白和连续换行；
- 单行展示，建议最多显示约 40 个字符；
- 不调用 LLM 生成标题；
- 用户重命名后不再随第一轮问题变化。

### 9.4 搜索

搜索范围包括：

- 会话标题；
- 用户问题；
- 回答正文；
- 原始选中文本。

搜索结果仍以会话为单位，摘要优先展示命中位置。第一版采用本地关键词搜索，不做语义搜索。

### 9.5 会话详情

顶部显示：

- 会话标题；
- 创建时间；
- 最后更新时间；
- 更多操作菜单。

原始选中文本以可折叠卡片显示：

- 短文本默认展开；
- 长文本默认折叠；
- 支持复制；
- 标注“本会话基于此内容”。

问答正文复用快捷面板的视觉语言，并支持文本选择和单轮回答复制。

用户在多个历史会话之间切换时，右侧继续显示上一份会话详情，直到新会话加载完成后直接替换；加载间隙不得闪现“新建会话”空状态。

### 9.6 会话操作

右键菜单和标题栏更多菜单提供：

- 重命名；
- 复制全部对话；
- 删除会话。

删除会话必须二次确认：

> 此操作将删除该会话的选中文本、问题和回答，且无法恢复。

正在录音或生成回答的会话不能删除，操作置灰并提示用户先结束当前任务。

### 9.7 继续追问

页面底部固定语音操作栏：

- 默认：“继续追问”；
- 录音中：“取消追问”和“结束追问”；
- 回答中：“正在思考……”；
- 失败后：保留错误信息，并允许重新提问。

第一版不增加文字输入框。

### 9.8 新建会话空状态

在主界面点击“新建会话”后，右侧显示：

> 开始一个新问题
>
> 点击下方按钮，然后说出你想问的问题。

主操作为“开始提问”。由于此时无法可靠获取其他 App 的新选中文本，主界面新会话默认没有原始选中内容，并提供提示：

> 如果需要针对其他应用中的内容提问，请先选中文字，再使用 Ask Anything 快捷键。

## 10. 跨界面协调

### 10.1 单一活动任务

任意时刻只允许一个 Ask Anything 录音或模型回答任务。快捷面板与主界面不得分别启动两个任务。

### 10.2 快捷面板转到主界面

- 已产生的回答立即出现在主界面；
- 后续流式增量继续写入同一轮次；
- 不重新请求模型；
- 面板隐藏，主界面成为主要展示位置。

### 10.3 主界面活动时再次触发

当主窗口处于前台且 Ask Anything 页面选中了会话时，快捷键继续该会话。主界面位于其他页面时，快捷键沿用外部快速提问路径，显示浮动面板并创建新会话。

### 10.4 活动会话保护

正在录音或回答时：

- 不能删除当前会话；
- 不能在另一会话中开始录音；
- 用户选择其他会话时，可以浏览，但活动状态仍归属于原会话；
- 页面应提供“返回正在回答的会话”入口。

## 11. 状态与异常处理

### 11.1 会话状态

| 状态 | 含义 | 是否持久化 |
|---|---|---:|
| 草稿 | 已进入提问流程，但尚未形成首轮问题 | 否 |
| 活跃 | 至少有一轮，当前可继续追问 | 是 |
| 回答中 | 某一轮正在接收流式回答 | 是 |
| 失败 | 最后一轮请求失败 | 是 |

“正在录音”属于运行时状态，不作为数据库中的长期会话状态。应用异常退出后，未完成录音不会恢复。

### 11.2 轮次状态

- `pending`：问题已保存，等待模型响应；
- `streaming`：正在接收回答；
- `completed`：回答正常完成；
- `failed`：请求失败，保存用户可见错误；
- `interrupted`：应用退出或请求被中断，保留已有部分回答。

### 11.3 特殊异常

- 没有配置 LLM：保留问题和配置错误，提供打开设置入口；
- 没有识别到问题：不创建新会话或新轮次；
- 应用在回答中退出：下次启动显示已保存的部分回答，并标为“回答未完成”；
- 原始选中文本缺失：隐藏空上下文卡片，对话仍可阅读和继续；
- 删除写入失败：保留界面数据并显示错误，不做乐观永久消失；
- 搜索无结果：显示“没有找到相关会话”和清除搜索入口。

## 12. 数据与隐私

### 12.1 默认行为

- Ask Anything 历史默认开启；
- 数据仅保存在本机应用支持目录；
- 第一版不设置自动过期时间，除非用户主动删除或清空；
- 不因为历史功能额外上传数据；
- 用于回答的模型请求仍遵循用户当前配置的 LLM 提供商。

### 12.2 设置项

在“模式 → 随便问”的模式详情中增加：

- “保存 Ask Anything 会话历史”，默认开启；
- “清空 Ask Anything 历史”。

关闭保存后：

- 已有历史继续可见，不自动删除；
- 新会话只在内存中存活；
- 快捷面板明确提示“本次会话不会保存”；
- 面板关闭或应用退出后，临时会话不可恢复。

“清空 Ask Anything 历史”必须二次确认，并删除全部会话、原始选中文本、问题和回答。

上述两个入口不出现在主界面 Ask Anything 历史列表中；历史页面只承担查找、阅读和会话管理。

### 12.3 复制与日志

- 用户主动复制时才写入系统剪贴板；
- 生产日志不得记录选中文本、问题、回答或完整 Prompt；
- 调试日志默认只记录会话 ID、轮次 ID、字符数量、状态和错误类别。

## 13. 第一版交付范围

### 13.1 必须实现

- 会话和轮次本地持久化；
- 快捷面板自动保存有效会话；
- 主界面独立 Ask Anything 页面；
- 日期分组、分页加载和关键词搜索；
- 查看完整对话和原始选中文本；
- 从旧会话继续语音追问；
- 重命名、复制全部和删除；
- “在 Type4Me 中打开”；
- 两个界面共享实时状态；
- 历史保存开关和清空入口；

## 14. 成功指标

第一版上线后重点观察：

1. 有效 Ask Anything 会话成功保存率；
2. 历史页面被打开的用户比例；
3. 从历史会话发起追问的比例；
4. 搜索后打开会话的成功率；
5. 快捷面板首次回答耗时是否发生回退；
6. 快捷面板关闭、ESC 和追问快捷键的回归错误率；
7. 历史列表达到 1,000 个会话时的加载与滚动性能；
8. 因上下文错误而把新问题追加到旧会话的事件数，目标为零。

所有指标只记录不含正文的计数与时延，不采集问题、回答或选中文本。

## 15. 验收标准

1. 用户仍可按照原有步骤通过快捷键完成首次提问；
2. 未形成问题的空操作不会产生历史记录；
3. 每个有效、失败或被隐藏的会话都能在主界面中找到；
4. 从快捷面板转到主界面时，不丢失流式回答和录音状态；
5. 从历史会话追问时，模型获得正确的原始选中文本和有效会话上下文；
6. 用户在其他 App 中重新触发快捷键时，不会误追加到旧会话；
7. 两个界面不会同时启动不同的 Ask Anything 录音；
8. 删除会话后，选中文本、问题和回答均不可再查询；
9. 关闭历史保存后，不再产生新的持久化会话；
10. 应用在流式回答中退出后，已保存的部分回答可见且标记为未完成；
11. 1,000 个会话下列表仍可正常分页、搜索和流畅滚动；
12. 标准录音和 Ask Anything 的快捷键、ESC、面板关闭按钮及录制指示器继续复用统一控制路径；
13. 从不包含此功能的旧版本升级时无需用户迁移或重建数据；
14. 生产日志不包含选中文本、问题、回答或完整 Prompt。

## 16. 已确认决策

| 决策 | 结论 |
|---|---|
| 历史管理放在哪里 | Type4Me 主界面独立 Ask Anything 页面 |
| 快捷面板是否重做 | 保持当前核心结构，仅增加轻量跳转和状态提示 |
| 是否允许继续旧会话 | 允许，使用原始上下文和历史轮次 |
| 是否在两个界面提供完整管理 | 否，主界面是唯一完整管理入口 |
| 是否加入文字输入 | 第一版不加入 |
| 是否自动生成标题 | 否，默认使用第一轮问题 |
| 是否默认保存 | 是，仅本地保存 |
| 是否自动过期 | 第一版不自动过期 |
| 是否与识别历史合并 | 否，产品页面与数据模型均保持独立 |
